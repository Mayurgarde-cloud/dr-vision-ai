# DR Vision AI — Diabetic Retinopathy Severity Classification

A full-stack, educational deep-learning web application that grades retinal fundus images into five
diabetic-retinopathy (DR) severity classes (0 – 4).

```
fundus image → crop · CLAHE · resize 224 → ResNet-50 (2048-d) + DenseNet-121 (1024-d)
             → feature fusion (3072-d) → StandardScaler → PCA → AdaBoost(Random Forest) → DR grade 0-4
                                                                      + class-activation heat-map
```

| Layer | Technology |
|---|---|
| Frontend | React 18 + Vite, Tailwind CSS, Recharts, Lucide icons, React Router |
| Backend | Python, FastAPI, SQLite (history), ReportLab (PDF report) |
| ML | PyTorch + torchvision (frozen backbones), scikit-learn (PCA, AdaBoost, Random Forest), OpenCV, pandas |

> ⚠️ **Educational project – not a medical device.** Results must never be used for diagnosis or treatment decisions.

---

## 1. Important: demo mode vs. trained model

The repository ships **without a trained model** (it needs a labelled dataset and ImageNet weights, neither of which can be bundled).
Until you train one, the backend runs in **demo mode**:

* The whole website works (upload, results, heat-map, PDF report, history, dashboard, …).
* Predictions come from a small image-statistics heuristic (`backend/app/services/demo_model.py`) that was fitted on the
  *synthetic* images in this repo. **It has no diagnostic value on real photographs.**
* Every page shows an amber *Demo mode* banner, results are tagged `mode: "demo"`, and the PDF report says so.

As soon as `backend/models/dr_model.joblib` exists (and PyTorch is installed) the backend switches automatically to the real
ResNet-50 + DenseNet-121 → PCA → AdaBoost/Random-Forest pipeline – restart the server after training.

The images in the UI and in `backend/data/dataset/` are **synthetic illustrations** (generated by `backend/ml/synthetic.py`),
not patient photographs. Replace the dataset with real data (section 4) for meaningful results.

## 2. Quick start

Requirements: **Python 3.10+** and **Node.js 18+**.

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt      # for CPU-only PyTorch see "Troubleshooting"
uvicorn app.main:app --reload --port 8000
```

API docs: <http://localhost:8000/docs> · health check: <http://localhost:8000/api/health>

### Frontend (development)

```bash
cd frontend
npm install
npm run dev                          # http://localhost:5173  (proxies /api and /files to :8000)
```

### Single-process "production" mode

```bash
cd frontend && npm install && npm run build      # creates frontend/dist
cd ../backend && uvicorn app.main:app --port 8000
# open http://localhost:8000  – FastAPI serves the built React app and the API together
```

## 4. Train the real model

### Dataset layouts

**A. Class folders** (default location `backend/data/dataset/`):

```
data/dataset/0_No_DR/*.jpg   1_Mild_DR/   2_Moderate_DR/   3_Severe_DR/   4_Proliferative_DR/
```
Folder names such as `0`, `No_DR`, `Mild`, `Proliferative_DR` are all recognised. Put a `dataset.json` next to them to
label the Dataset page:
```json
{ "name": "APTOS 2019", "source": "Kaggle / APTOS 2019 Blindness Detection" }
```

**B. CSV labels** (e.g. APTOS 2019 `train.csv` with `id_code,diagnosis`):
```bash
python -m ml.train --csv /path/train.csv --image-dir /path/train_images --dataset-name "APTOS 2019"
```

### Train → evaluate

```bash
cd backend
python -m ml.train                        # writes validation-only candidate to models/candidate
python -m ml.train --augment 2 --pca-components 256 --ada-estimators 20   # optional tuning
python -m ml.evaluate --model-dir models/candidate  # one-time test evaluation after validation selection
```

* Uses a **stratified 70 / 15 / 15** train / validation / test split (seeded, saved to `models/splits.json`).
* Scaler, PCA and the classifier are fitted on training data only. Validation metrics guide selection; test images are not opened during training.
* Training caches train and validation features separately. Test features are extracted only by the one-time evaluation command after selection.
* First run downloads the ImageNet weights (~100 MB for ResNet-50 + ~30 MB for DenseNet-121) into the torch cache – internet needed once.
* Outputs: a separate candidate bundle, validation metrics, split manifest, and dataset metadata under `backend/models/candidate/`.
  The trainer never overwrites the production bundle. After validation selection, the test evaluator writes `test_metrics.json` and refuses repeat evaluation.

Restart `uvicorn` afterwards so the new model is loaded.

### No dataset yet? Generate the synthetic demo set

```bash
python -m scripts.make_sample_dataset     # 231 synthetic images (already included in the repo)
python -m ml.train --no-pretrained        # offline pipeline smoke test – accuracy figures are NOT meaningful
```

|---|---|---|
| GET | `/api/health` | Status, model mode (`trained` / `demo`), torch availability |
| POST | `/api/predict` | `multipart/form-data` field `file` → prediction (class, confidence, probabilities, image / heat-map URLs) |

| GET | `/api/predictions/{id}` | One prediction |
| GET | `/api/predictions/{id}/report` | PDF report |
| DELETE | `/api/predictions/{id}` · `/api/predictions` | Delete one / clear all (also removes stored images) |
| GET | `/api/dashboard` · `/api/dataset` · `/api/model/performance` | Data for the corresponding pages |

Upload validation: JPG/JPEG/PNG only, ≤ 5 MB, must decode as an image, ≥ 64 px per side. Errors return JSON `{"detail": "…"}`
with 400 / 413 / 404. Images that do not look like fundus photographs are still processed but returned with a `warnings` entry.

## 8. Design notes & limitations

* **Heat-map ("Grad-CAM")**: the final classifier (AdaBoost/Random Forest) is not differentiable, so a class-activation map is
  computed from the ResNet-50 layer-4 features with a linear head fitted on the pooled features. For a global-average-pool +
  linear model this equals Grad-CAM, but it explains the *surrogate* head, not the ensemble itself. In demo mode the heat-map
  simply highlights lesion-like blobs found by the heuristic.
* Backbones are used as **frozen feature extractors** (no fine-tuning). Fine-tuning, larger datasets, calibration and external
  validation are natural next steps.
* Class imbalance is handled with balanced Random-Forest weights; no resampling is done.
* The trained bundle is a scikit-learn pickle – load it with the same scikit-learn major version it was trained with.
* The prediction-time image is cropped to the fundus circle, CLAHE-enhanced and resized to 224 × 224 (identical to training).
* Reference: Mustafa et al., *Multi-Stream Deep Neural Network for Diabetic Retinopathy Severity Classification Under a Boosting
  Framework*, IEEE Access, 2022 – <https://doi.org/10.1109/ACCESS.2022.3217216>.

## 9. Troubleshooting

* **`pip install torch` is huge / fails** – install a CPU build first: `pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu`, then `pip install -r requirements.txt`.
* **Banner says "Demo mode" after training** – restart `uvicorn`; check `curl localhost:8000/api/health` (`reason_code` tells you why: `no_model`, `no_torch`, `load_error`).
* **"Cannot reach the server" in the UI** – start the backend on port 8000 (or set `VITE_BACKEND_URL` for the dev proxy).
* **Port already in use** – `uvicorn app.main:app --port 8001` and `VITE_BACKEND_URL=http://127.0.0.1:8001 npm run dev`.
* **Training is slow** – feature extraction is the bottleneck (a GPU helps a lot); it runs once and is cached.

## 10. Reproducible SVM experiment (Windows PowerShell)

The production bundle remains `backend/models/dr_model.joblib`. To repeat the validation-only RBF-SVM selection using the supplied cached train/validation features, run from `backend`:

```powershell
python -m scripts.train_svm_candidate --cache-dir models/experiment_aug1 --splits models/splits.json --out-dir models/experiment_svm_v1
```

This reads only the train and validation caches, fits preprocessing and probability calibration on training features, selects by validation macro F1, and writes a separate bundle with per-candidate metrics. It never opens the test cache. Use the test split only once after selecting the candidate. To run a selected candidate without replacing production:

```powershell
$env:DR_MODEL_PATH = (Resolve-Path .\models\experiment_svm_v1\dr_model.joblib).Path
python -m uvicorn app.main:app --reload --port 8000
```

The application labels these values **class scores**. Even internally calibrated scores are not probabilities of disease in a patient and do not establish clinical validity. Models and heatmaps are for research/education only.

The supplied source images and CSV labels are external to the repository. The original split-training command accepts explicit paths; for example:

```powershell
python -m ml.train_splits --train-csv 'E:\Diabetic Dataset\train_1.csv' --train-image-dir 'E:\Diabetic Dataset\train_images\train_images' --val-csv 'E:\Diabetic Dataset\valid.csv' --val-image-dir 'E:\Diabetic Dataset\val_images\val_images' --out-dir models\new_split_run
python -m ml.evaluate --model-dir models\new_split_run --test-csv 'E:\Diabetic Dataset\test.csv' --test-image-dir 'E:\Diabetic Dataset\test_images\test_images'
```

The command never reads the test split. Prefer the cached validation-only candidate workflow above when matching its features and preprocessing metadata.

After validation selection, run the independent test evaluation exactly once:

```powershell
python -m scripts.evaluate_selected_test --cache-dir models/experiment_aug1 --splits models/splits.json --model-dir models/experiment_svm_v1
```
